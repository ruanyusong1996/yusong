# 海底捞集团工会工作数据看板

一个可多人协作的工会数据看板：**前台大屏看板** + **后台数据管理**，数据存在服务端，多人同时访问共享同一份数据，改完秒级同步。

---

## 一、快速开始

```bash
# 1. 进入目录
cd output

# 2. 安装依赖（首次运行，仅一次）
npm install

# 3. 启动服务
npm start
# 或指定端口
node server.js --port=8080
```

启动后浏览器打开：

| 页面 | 地址 | 用途 |
|---|---|---|
| 数据看板 | http://localhost:5300/ | 大屏展示，点击数字跳明细 |
| 后台管理 | http://localhost:5300/admin.html | 增删改数据 |

### 局域网内多人共享

1. 找到本机内网 IP：
   ```bash
   # macOS
   ipconfig getifaddr en0
   # Linux
   hostname -I | awk '{print $1}'
   ```
2. 把 `http://<你的IP>:5300/` 发给同事，例如 `http://192.168.1.20:5300/admin.html`
3. 大家访问同一个地址 → 数据天然共享。A 改一条，B 的看板 1 秒内自动刷新。

> 首次从别的电脑访问可能被系统防火墙拦截，需要允许 Node 进程接听入站连接。

## 三、数据存取原理

`data-store.js` 启动时会探测同源的 `/api/health`：

- **探测成功** → **API 模式**（多人共享）
  - 读数据：`GET /api/data`
  - 写数据：`PUT /api/data`（服务端原子写入 `server-data.json`）
  - 实时同步：`EventSource /api/stream`（SSE）——服务端推、浏览器自动重连
- **探测失败** → **本地模式**（单人离线）
  - 使用 `localStorage`，跨 tab 靠 `storage` 事件同步

所以：

- 用 `npm start` 打开 → 自动多人共享
- 直接双击 `index.html`（`file://`）打开 → 自动本地模式，无需后端也能看

页面右上角有状态徽章：**云端共享**（青色）/ **本地存储**（绿色）/ **已断线**（红色）。

## 四、API 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/health` | 健康检查，返回 `{ok, ts, clients, version, persistent, storageMode, dataMtime}`；**`persistent` 用来判断数据是否会随重新部署丢失** |
| `GET` | `/api/data` | 拉取全部数据 |
| `PUT` | `/api/data` | 覆盖保存全部数据（JSON body），成功后向所有 SSE 客户端广播；空数据 / 会把全部行清空的写入会被拒绝（400） |
| `POST` | `/api/reset` | 重置为 `seed-data.json` 初始数据（写前自动快照） |
| `GET` | `/api/config` | 拉取看板配置（文字/主题/布局/模块/指标/图表/统计表） |
| `PUT` | `/api/config` | 覆盖保存看板配置，并向所有 SSE 客户端广播 `config` 事件 |
| `GET` | `/api/storage` | 🔒 存储诊断：数据目录、是否持久、行数、快照数量与修复建议 |
| `GET` | `/api/backups` | 🔒 快照列表（含时间、类型、行数、大小） |
| `POST` | `/api/backups` | 🔒 手动打一份快照 `{kind: 'data'\|'config'}` |
| `POST` | `/api/backups/restore` | 🔒 用指定快照覆盖回去 `{name}`（覆盖前自动再存一份当前版本） |
| `POST` | `/api/auth/login` \| `logout` \| `password` | 🔑 登录 / 退出 / 改密码 |
| `GET` | `/api/auth/status` | 🔑 当前会话角色 |
| `GET` | `/api/stream` | SSE 事件流，事件类型：`hello` / `update` / `config` |

> 🔒 = 需要后台密码；🔑 = 鉴权相关；其余需要看板密码（`/api/health`、`/login.html` 公开）

示例：

```bash
# 查看数据
curl http://localhost:5300/api/data

# 重置数据
curl -X POST http://localhost:5300/api/reset
```

## 五、数据字段说明

数据按 4 个模块组织，每一模块为 `{ title, subtitle, headers, rows }`：

| 模块 Key | 标题 | 记录数 | 主要字段 |
|---|---|---|---|
| `01-组织建设` | 工会组织建设 | 20 | 工会名称、依托公司、工会主席、职工人数、组建状态、工会级别、**当前进度 / 进度日期 / 工作负责人**、备注 |
| `02-走访慰问` | 员工走访慰问 | 56 | 慰问类型、员工姓名、所在大区、部门/门店、慰问日期、物品金额、事由、经办人 |
| `03-员工活动` | 员工活动 | 52 | 活动日期、内容、形式、类型、区域、组织部门、**经办人**、覆盖人数、支出金额 |
| `04-经费收支` | 工会经费收支 | 7 | 工会名称、收支类型、经费项目、年初金额、支出金额、结余、事由、经办人 |
| `05-经费瀑布` | 各工会经费瀑布（桥梁） | 14 | 工会名称、工会全称、**收支类型（期初/入账/支出/结余）**、经费项目、金额（元）、备注 |

看板上的所有汇总数字（工会总数、已组建数、走访人次、活动场次、经费结余……）都是**从明细实时计算**的，不是写死的。

### 五·补 经费瀑布（桥梁）图怎么用

看板「四、经费收支情况」最下方那张图：**每个工会占一行**，行内依次是 `期初 → 入账 → 支出 → 结余` 四段，一眼看出钱从哪来、花到哪去、还剩多少。

- 数据来源是长表 `05-经费瀑布`：**一行 = 某个工会的一个科目**。同一个阶段可以有多行（比如 3 笔入账、2 笔支出），自动累加。
- **结余默认自动计算** = 期初 + 入账 − 支出；只有在表里填了「结余」类型的行，才按手工值显示（账实不符时可强行平账）。
- 后台两个入口都可以改：
  - 「五、经费瀑布」页签 → 像普通表格一样逐行增删改；
  - 「🌉 瀑布图编辑」→ 左侧选工会，右侧改期初、增删入账/支出项目、勾选「手工指定结余」，底部实时显示 `期初 ＋ 入账 － 支出 ＝ 结余`。
- **新增工会组织**：页签上的「＋ 新增工会组织」按钮（组织建设表与瀑布表都有），填一次会同时登记进「一、组织建设」（工会总数/组建率等指标同步更新）和「05-经费瀑布」（图上立刻多一行）。
- 这张图和其它图表一样可在「🎨 看板配置 → ⑥ 图表样式」里改标题、配色、排序、高度、小数位；图表类型 `waterfall` 有三个专属字段：分组字段（工会名称）、阶段字段（收支类型）、项目字段（经费项目）。
- **金额单位是「元」，保留 3 位小数**（看板标签/提示与后台编辑器一致）。v1.4 之前的版本用的是「万元」，升级时服务端会把 `05-经费瀑布` 的金额一次性 ×10000 换算成元并落盘，只换算一次（靠表头 `金额（元）` 判断，重启不会重复放大）。
- **保存是「合并」而不是整表覆盖**（v1.5.0）：点「确认」时先拉一份服务端最新数据做基底，只重写本次编辑过的工会；没在左侧列表里出现的工会原样保留。因此编辑器开着的时候，别人（另一个标签页/手机）新增的工会不会被旧快照抹掉。
- **一个工会永远至少保留一行**（v1.5.0）：万一某个工会的科目被全部删掉，保存时会自动补一条 0 元期初，工会不会从瀑布图上消失；同时「原本有金额、现在被清成 0」会在保存前弹确认，避免手滑清零。
- **名单不一致会自动提示**（v1.5.0）：底部会对比「04-经费收支」和瀑布表的工会名单与金额，出现「只在 04 表里有」「瀑布表金额全是 0」时给出清单和 **「按 04 表补全」** 按钮，一键补回/补全（只补空缺，不覆盖已有非零数据），核对无误再点「确认」保存。

> 升级说明：`05-经费瀑布` 表如果是第一次出现，服务端会**按现有「04-经费收支」的真实数据自动推导**出来（不会凭空编造金额），推导结果里带了「请核对」备注，改完即可。

### 五·补二 筹建进度 / 月度统计 / 干事月度卡片（v1.6 新增）

#### ① 筹建中工会的「筹建进度表」（一、组织建设情况最下方）

- 只显示 `组建状态 = 筹建中` 的工会（当前 7 个），列是 **工会名称 / 当前进度 / 进度日期 / 工作负责人**。
- 「当前进度」在后台是下拉框，阶段固定为：`未启动 → 方案制定 → 会员登记 → 报批审批 → 选举筹备 → 已成立`；看板上按阶段位置自动画进度条（未启动 0%、已成立 100%）。没填就是一条 `—`，不会画一条空槽。
- 想加阶段列（比如「方案审批日期」「选举完成日期」）：
  1. 后台「数据管理 → 列管理」给 `01-组织建设` **加一列**；
  2. 后台「看板配置 → ⑦ 统计表」编辑 `tbl-org-preparing`，在「明细列」里**加一行**，选上新字段、给个表头；
  3. 保存配置，看板立刻多一列。

  这就是为什么这张表用的是 `type: 'list'`（明细列表表）：**一行一条记录、列完全由你配**，不像统计表那样被固定成「分组 + 聚合」。

#### ② 走访慰问 / 员工活动的「月度」数字

两个板块各新增一张月度图：**柱 = 人次（场次），线 = 金额（右轴）**。

- 分组方式是 `dateGroup: 'month'` —— 从日期列里取「年-月」。`2026-08-05`、`2026/8/5`、`2026.8.5`、`2026年8月5日`、Excel 日期序列号都能认。
- **日期不规范的行走不进月度图**（比如 `02-走访慰问` 里有 20 行「慰问日期」写的是「线上邮寄慰问品」）。这些行**仍然计入总人次/总场次**，只是月度分布里看不到——等你把日期补齐，它们会自动出现在对应月份。
- 金额列（`慰问物品金额（元）` / `支出金额（元）`）目前还是空的，所以金额线贴在 0 上；补录后线自动抬起来，不用改配置。

#### ③ 「工会干事月度数据卡片」（矩阵表）

- 走访慰问、员工活动各一张：**行 = 经办人（工会干事），列 = 月份（自动派生），最后一列 = 个人合计，最后一行 = 月度合计**。
- 列不写死：`colDateGroup: 'month'` 让列从数据里的月份自动生成，**下个月有了新数据会自动多一列**，不用改配置。
- 员工活动的「经办人」是 v1.6 新加的列，目前还没有数据，所以那张表显示「（暂无数据，请先在后台填写「经办人」列）」。填了就会出人。
- 想把矩阵从「人次/场次」改成「金额矩阵」：后台编辑该表，把「单元格统计方式」改成**求和**、「单元格统计字段」选金额列即可。

> 升级说明：新增的三张表、两张图、五个区块会由服务端 `mergeAdditions()` **只做加法**补进线上已有配置，你改过的标题/配色/列宽一律不动。
> `01-组织建设` 与 `03-员工活动` 的新列由启动时的 `ensureColumns()` 自动补上（数组行、对象行两种形态都处理），补完写入磁盘且只执行一次。

### 五·补三 批量删除 / 收集端口 / 支出汇入（v1.7 新增）

#### ① 数据批量删除

- 后台「数据管理」每张表的最左边多了一列**复选框**，表头是**全选 / 取消全选**。
- 勾选后工具条上出现 **「🗑 删除所选（N）」**，右侧同步显示「已选 N 条」，被勾选的行整行高亮。
- 点删除会弹二次确认，说明将删哪张表、多少条，并提醒先去「安全设置 → 备份」确认有快照。
- **搜索状态下只删筛选出来的行**：先搜索再全选，未显示的行不会被误删（已回归测试覆盖）。
- 删除是**一次性整表写回**，不是逐行 PUT —— 连着多次 PUT 会互相覆盖（历史踩过的坑）。

#### ② 收集端口（10 个独立填报账号）

- 独立入口：`/collect.html`，界面与管理后台完全不同，只做「填 + 看自己填的 + 改自己的」。
- 后台「📥 收集端口」页签可管理 10 个端口：**改端口名 / 用户名 / 重置密码 / 启用停用 / 授权可填报表 / 一键清空该端口数据**。
- 账号由管理员设置后下发给填报人；填报人登录后可在右上角「修改账号密码」自行改（用户名在 10 个端口间不能重复）。
- **端口之间互不干扰**：登录只看得到自己提报的记录，改/删别人的记录一律 **403**。
- 端口会话**读不到后台数据**（`/api/data` 返回 401），也不含密钥；密码用 scrypt + 随机 salt 哈希存储。

#### ③ 提报人

- 三张业务表（`01-组织建设` / `02-走访慰问` / `03-员工活动`）都新增 **「提报人」** 列，由服务端按当前登录端口自动盖章，前端传什么都不算数。
- 后台该列**只读**，能直接看到每条数据是谁提报的。

#### ④ 业务支出自动汇入经费收支

| 来源表 | 金额列 | 对齐列 | 汇入目标 |
|---|---|---|---|
| `02-走访慰问` | `慰问物品金额（元）` | `费用列支账户` | `04-经费收支` 的 `慰问支出汇入（元）` |
| `03-员工活动` | `支出金额（元）` | `费用列支账户` | `04-经费收支` 的 `活动支出汇入（元）` |

- 对齐规则：**来源行的「费用列支账户」 == `04-经费收支` 行的「工会名称」**（两端都做去空格 + 全角括号归一化后比较）。
- 汇入后由既有公式推出其它数：
  - `支出合计（元） = 支出金额（手工其它支出） + 慰问支出汇入（元） + 活动支出汇入（元）`
  - `当前结余（元） = 期初金额 + 入账金额 − 支出合计（元）`
  - `当前结余（万元） = 当前结余（元） ÷ 10000`
- 04 表新增的 5 列全部是**派生只读列**，后台表格能看到，编辑弹窗里不会出现（防止手改把账改乱）。
- **读取时和写入前都会重算一遍**：即使客户端送来的汇入列是脏数据，存下来的也一定是公式结果。
- 兜底：某工会没登记期初/入账金额但有结余时，会按结余反推期初并记录告警，可在备份里找回旧值；账户名对不上时会在后台给出「未匹配」清单。

> 升级说明：`schema.js` 是**前后端共用的字段定义**（浏览器挂 `window.BUILTIN_SCHEMA`，Node 走 `module.exports`），服务端校验端口提报数据也用它；
> 但**服务端只读不写 schema** —— 把 schema 写进数据文件会冲掉前端自定义的下拉控件。
> 新增的「提报人」列与 04 表的三个汇入列由 `ensureColumns()` 自动补齐（数组行、对象行两种形态都处理）。

## 六、部署到 Railway（5 分钟拿到公网链接）

Railway 每月送 **$5 免费额度**，你这服务内存 60MB、流量几乎为零，跑几个月都没问题。部署后拿到一个 `https://xxx.up.railway.app` 的固定链接，**关电脑也不影响**，可发给任何人访问。

### 步骤 1：把代码推到 GitHub

```bash
cd output            # 进入项目目录

# 如果你已经有 GitHub 账号并配置了 SSH key
git init
git add .
git commit -m "init: 工会数据看板"
git branch -M main
git remote add origin git@github.com:<你的用户名>/gh-dashboard.git
git push -u origin main
```

> 还没配 SSH key？最快的方式是用 [GitHub CLI](https://cli.github.com/)：`brew install gh && gh auth login`，然后 `gh repo create gh-dashboard --public --source=. --push` 一行搞定。
>
> 或者用 HTTPS：`git remote add origin https://github.com/<用户名>/gh-dashboard.git`，第一次推送要输用户名 + [Personal Access Token](https://github.com/settings/tokens)。

### 步骤 2：在 Railway 创建项目

1. 打开 https://railway.app/new
2. 点击 **Deploy from GitHub repo**
3. 授权 Railway 访问你的 GitHub，选择刚才创建的 `gh-dashboard` 仓库
4. Railway 自动检测到 Node 项目，按 `railway.toml` 配置开始构建部署

### 步骤 3：拿到公网链接

部署完成后：
1. 在 Railway 项目页点击你的服务
2. 切到 **Settings** → **Networking** → **Generate Domain**
3. 复制生成的 `https://xxx.up.railway.app` —— 这就是你的公网链接

### 步骤 4：把链接发给大家

看板：`https://xxx.up.railway.app/`
后台：`https://xxx.up.railway.app/admin.html`

两个人同时打开后台，**任一人改动，另一人秒级看到**。

> ⚠️ **重要 - 数据持久化**：Railway 容器**重新部署 / 重启时，代码目录 `/app` 会被整体替换**，
> 数据文件写在里面就会丢。这就是「每次改完就变回 20/13/7」的原因。
>
> **正确的解决办法：挂一块 Volume**（不是加 Postgres）。入口在 **`⌘K` 命令面板 → `volume`**，
> 或**画布空白处右键 → Volume**，挂载路径必须填 `/data`。详见 `DEPLOY_GUIDE.md` 第 5 步。
> 挂上后程序会自动识别 `/data`，**不需要改任何代码**；`GET /api/health` 的 `persistent`
> 会变成 `true`，后台「安全设置 → 数据存储与备份」也会显示 🟢 已开启。
>
> 没挂卷时程序不会静默失败：后台顶部会常驻红色告警条，`/api/health` 会如实报 `persistent: false`。
> 保险起见，也可以在后台点「导出 JSON」手动留一份本地备份。

## 七、注意事项

1. **并发写入**：服务端对写操作做了串行化（`writeChain`）+ 原子替换（先写 `.tmp` 再 rename），避免并发把文件写坏。
2. **多人同时改同一条**：采用「后写覆盖」策略（last-write-wins）。如果需要字段级合并或版本冲突检测，需要再加一层乐观锁。
3. **登录鉴权**：看板页需「看板密码」，后台页与所有写接口需「后台密码」；两个密码可在后台「安全设置」里随时修改。密码用 scrypt + 随机盐哈希存储，会话走 HttpOnly Cookie（12 小时有效、内存态、重启即失效）。
4. **数据备份**：直接复制 `server-data.json` 即可；后台页面的「导出 JSON」也能下载快照。
5. **看板配置会被服务端兜底收敛**：`PUT /api/config` 与 `GET /api/config` 都会跑一遍
   `normalizeConfig()` —— 图表色板必须是合法颜色数组、列宽必须是 1~12 的整数，
   不符合的会被自动修正并在响应里回传 `warnings`。**这样即使前端有类型 bug、
   或磁盘上已经存了一份坏配置，看板也不会渲染失败。**（历史故障：色板被存成逗号
   字符串 `"#4DD8FF,#5FE0FF,…"`，ECharts 逐字符取色拿到 `'#'` →
   `addColorStop` 抛异常 → 所有图表渲染成黑色。）
6. **SSE 与代理**：经 Nginx / 云负载均衡时务必关闭响应缓冲，否则推送会被攒着不发出。

## 八、回归测试

改完代码后**务必全跑一遍**，尤其是 `test:persist` —— 它守的就是「重新部署数据被清空」这条底线。

```bash
npm run seed                   # 改完 word 里的 seed-*.js 后，同步生成 seed-*.json（服务端读 JSON）

npm run test:v16               # 72 项：月度分组 / 明细列表表 / 干事×月份交叉表 / 老数据补新列
npm run test:persist           # 53 项：数据目录解析 / 重启后数据还在 / 防误清空 / 备份恢复 / 降级告警
npm run test:api               # 86 项：鉴权、配置、备份、静态文件白名单
npm run test:e2e               # 217 项：真实浏览器跑看板 + 后台（持久目录，含瀑布图/筹建进度/月度图/干事矩阵）
npm run test:e2e:nonpersist    # 226 项：模拟「卷没挂上」，验证告警条与标红
npm test                       # 依次跑前四个（60+72+53+86 = 271 项，不含浏览器 E2E）
```

> 全量合计 **714 项**（60 + 72 + 53 + 86 + 217 + 226）。

| 脚本 | 覆盖内容 |
